# Excel-Link 名前定義（Named Ranges）リファレンス

fusion_place Excel-Link の各設定項目の設定値は、シートローカルな「名前」に保存されています。このリファレンスは全設定項目の一覧です。記述内容は、将来、変更される可能性があり、その場合の互換性は保証されていません。このリファレンスはAIがExcel-Linkシートを設定し、あるいは解読する際の一助となることを意図したものであって、フュージョンズが保証する安定した仕様を記述するものではない点にご留意ください。

## 1. 名前の構築方法

すべての名前は **シートローカルスコープ** で保存される。
名前は「プレフィックス」＋「ラベル」を連結して構築される。
プレフィックスはコードが自動生成する部分、ラベルが各設定項目の識別子である。

> **シートローカルスコープの2つの表現**: 同じ名前でも、保存・参照の経路によって表現が異なる。
> - **VBA内部表現**（`Names.Add NameLocal:=True`）: 名前文字列自体に `'シート名'!` 修飾子が付く。例 `'Sheet1'!_FUSIONPLACE_001_RANGE`
> - **OOXML（.xlsx の workbook.xml）の実体**: 名前は修飾子なし（`_FUSIONPLACE_001_RANGE`）で、スコープは `localSheetId` 属性で表現する。
>
> openpyxl 等でファイルを生成する場合は **後者**に従う。`DefinedName(name="_FUSIONPLACE_...", localSheetId=シートのインデックス)` とし、`name` に `'シート名'!` を含めてはならない（含めると不正な名前として無視される）。シート名は参照値（`attr_text` / `RefersTo`）側にのみ現れる。
> 以下 1.1 のプレフィックス表は VBA 内部表現で示すが、生成時は修飾子を除いて読むこと。

### 1.1 プレフィックスの構造

すべての名前に共通する基底プレフィックスは `'シート名'!_FUSIONPLACE_`（コード上の `ModifiedPrefix`）。
この基底に、設定の種類に応じた文字列・連番が付加される。設定は2つの大区分に分かれる。

**(1) シート処理要領設定**

| 区分 | プレフィックス | 構築式 |
|---|---|---|
| (1a) データ取得処理 | `'シート名'!_FUSIONPLACE_` | 基底と同じ |
| (1b) データ反映処理 | `'シート名'!_FUSIONPLACE_` | 基底と同じ |
| (1c) テンプレート処理 | `'シート名'!_FUSIONPLACE_KEYITR_` | 基底 + `KEYITR_` |
| (1d) 行バインディング | `'シート名'!_FUSIONPLACE_KEYITR_RB_NNN_` | 基底 + `KEYITR_RB_` + 連番 + `_` |

> (1a) と (1b) はプレフィックスが基底と同一で、画面上の区分のみが異なる。
> (1d) 行バインディングは、画面上は (1c) テンプレート処理の下位区分だが、番号は独立させている。

**(2) リンク領域設定**

| 区分 | プレフィックス | 構築式 |
|---|---|---|
| (2a) リンク領域 | `'シート名'!_FUSIONPLACE_NNN_` | 基底 + 連番 + `_` |
| (2b) リンク領域 ＞ キー割当 | `'シート名'!_FUSIONPLACE_NNN_KB_MMM_` | (2a)のプレフィックス + `KB_` + 連番 + `_` |

### 1.2 完成する名前の例

プレフィックスの末尾に、後述の表にある **ラベル** をそのまま連結する。

```
(1a) ゼロ空白表示         'Sheet1'!_FUSIONPLACE_ZEROASBLANK
(1c) テンプレート範囲     'Sheet1'!_FUSIONPLACE_KEYITR_TEMPLATERANGE
(1d) 行バインディングDIM  'Sheet1'!_FUSIONPLACE_KEYITR_RB_001_RBDIM
(2a) リンク領域の範囲     'Sheet1'!_FUSIONPLACE_001_RANGE
(2a) 対象元帳ラベル       'Sheet1'!_FUSIONPLACE_001_LEDGERLABEL
(2b) キー割当のDIM        'Sheet1'!_FUSIONPLACE_001_KB_001_KEYDIM
```

> **注意**: ラベルにプレフィックスを再度含めない。たとえばテンプレート処理の
> ラベルは `TEMPLATERANGE` であって `KEYITR_TEMPLATERANGE` ではない。
> `KEYITR_` はプレフィックス側に含まれる。

### 1.3 連番（NNN / MMM）

- **`001` 始まり**の3桁ゼロ埋め（`Format(Seq, "000")`）。`000` は使わない。
- `NNN` … リンク領域・行バインディングの通し番号。それぞれ独立に `001` から振る。
- `MMM` … キー割当・テキスト式分割の通し番号。各リンク領域内で `001` から振る。

### 1.4 COL/ROW 分割方式（単一セルを指定する項目）

単一セルを指す項目は、**列全体**と**行全体**を別々の名前として保存する。
ラベルの末尾に `COL` / `ROW` が付く2つの名前で1セルを表す。

```
保存: ラベル+COL → セルの EntireColumn（例 Sheet1!$C:$C）
     ラベル+ROW → セルの EntireRow   （例 Sheet1!$3:$3）
読込: Intersect(COL, ROW) → 交点セル（C3）を取得
```

**設計意図**: セル参照（`$C$3`）で保存すると、ユーザーがそのセルを含む範囲を
ドラッグ移動・切り取り貼り付けした際に、名前定義がセルに追随して動いてしまう。
列全体×行全体に分解することで、特定セルとの結合を断ち、シート上の座標軸だけを記憶する。
（行・列の挿入・削除に対しては、COL/ROW それぞれが自動追従する。）

以下の表で型が「列全体/行全体」の項目が、この方式の対象。
ラベル末尾に `COL` と `ROW` を付けた2名前を作る。

|---|---|---|---|
| `REGIONNAME` | 文字列 | リンク領域の名称（任意の識別名） | |
| `RANGE` | セル範囲 | データを取得・反映するセル範囲 | リンク領域の本体 |

| `EDITIONKEYRANGE` | 列全体/行全体 | エディションキーを参照するセルの位置 | COL/ROW分割 |

| `TOCONVERTDATETIMETEXT` | Boolean | 日時テキストを変換するか | 新規作成時デフォルト `TRUE` |

### 3.2 (2b) キー割当（KeyAssignment）

プレフィックス: `'シート名'!_FUSIONPLACE_NNN_KB_MMM_`（MMM = `001` 始まり3桁）

リンク領域の下位区分。複数定義可能で、MMM で識別する。
ひとつのキー割当が「あるディメンションのメンバラベルをどこから読むか」を定める。
`KEYDIM`（ディメンションラベル）と `KEYRANGE`（読み取り位置）が対になって初めて有効になる
（両方揃わないキー割当は読込時に破棄される）。

| ラベル | 型 | 意味・役割 | 備考 |
|---|---|---|---|
| `KEYDIM` | 文字列 | キー割当が対応するディメンションのラベル | |
| `KEYRANGE` | セル範囲 | キーメンバーラベルを読み取る位置 | 下記の3つの型をとる |

**KEYRANGE の3つの型と方向正規化**

`KEYRANGE` は指定された範囲の形状から型が判定され、保存時に正規化される。

| キーの並び方 | 指定する範囲 | 正規化後（保存される形） | 用途 |
|---|---|---|---|
| 固定（単一メンバ） | 単一セル | 単一セル（`$C$2`） | 会計年度・店舗など、領域全体で固定のキー |
| 縦方向に展開 | 1列の範囲 | その列全体（`$B:$B`） | 行ごとに異なるキー（例: 各行が別の勘定科目） |
| 横方向に展開 | 1行の範囲 | その行全体（`$4:$4`） | 列ごとに異なるキー（例: 各列が別の月） |

> **注意（方向の直交）**: 「縦方向に展開するキー」は **列全体**（`EntireColumn`）として、
> 「横方向に展開するキー」は **行全体**（`EntireRow`）として保持される。
> キーが並ぶ方向と、保持される全体参照の向きが直交する点に注意。
> 生成時は最初から正規化後の形（列全体 `$B:$B` / 行全体 `$4:$4` / 単一セル `$C$2`）で
> 書いておくのが安全。具体的な行範囲（`$B$7:$B$14`）でもExcel-Link側で正規化されるが、
> 正規化形で書けば実機の保存結果と一致する。

> **固定キーの活用例**: 領域全体で固定したいキー（会計年度・表示形式・業務責任単位など）は、
> 値を書いた単一セルを `KEYRANGE` に指定する「固定キー」として表現できる。
> リンク領域の `RANGE` の外（ヘッダー部など）にキー値セルを置き、それを参照すればよい。

> **取得スキップの活用**: ある列・行のキーセルを空白にしておくと、その列・行は取得対象から
> 外れる。予算列・実績列の隣に差異列を設け、差異列のキーだけ空白にして Excel 数式
> （実績−予算）を仕込む、といった構成が可能。

## 4. 値の保存形式

名前の `RefersTo`（openpyxl の `attr_text`）に格納する値の形式。

| 型 | 格納形式 | 例 |
|---|---|---|
| Boolean | `TRUE` / `FALSE` | `TRUE` |
| 整数 | 数値そのまま | `1` |
| 文字列 | ダブルクォート囲み（内部の `"` は2重化） | `"GeneralLedger"` |
| 列全体（COL） | シート名付き列参照 | `Sheet1!$C:$C` |
| 行全体（ROW） | シート名付き行参照 | `Sheet1!$3:$3` |
| セル範囲 | シート名付き範囲参照 | `Sheet1!$B$4:$F$20` |

> **文字列値の `=` の扱い（重要）**: VBA内部表現では文字列は `="..."`（先頭に `=`）の形をとる（`SaveString` が生成し、読込側 `GetStringValue` が先頭1文字を除去して復元する）。しかし **OOXML の workbook.xml に直接書く際は先頭の `=` を付けず `"..."` とする**。openpyxl で `="..."` と書くと Excel が数式として評価してしまい、`Name.Value` が想定とずれて文字列が壊れる（LEDGERLABEL や KEYDIM が空に見える）。生成時は `=` なしの `"GeneralLedger"` 形式にすること。
> 空文字列・Null の場合はその名前自体を作成しない（省略される）。

## 5. 整数コード値

整数型の項目がとるコード値。

### 5.1 REGIONTYPE（領域タイプ）

| 値 | 意味 |
|---|---|
| `0` | データ領域（元帳セル値） |
| `1` | 名称領域（メンバ名称・プロパティ等） |
| `2` | テキスト式領域 |

### 5.2 APPLICABLEACTION（適用アクション）

| 値 | 意味 |
|---|---|
| `0` | 取得のみ |
| `1` | 取得・反映の両方 |
| `2` | 反映のみ |

### 5.3 SIGN（符号処理）

| 値 | 意味 |
|---|---|
| `0` | 科目属性に従う（勘定科目の貸借区分に従う。既定値として推奨） |
| `1` | 借方 |
| `2` | 貸方 |
